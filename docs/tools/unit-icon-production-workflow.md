# 作战单位图标生产工艺

本文件沉淀 `伦敦上空的鹰` 六类飞机单位图标打磨后的通用工艺。它不是伦敦飞机专用说明，而是动画六层制作工艺中第 4 层“作战单位资产、尺度与贴地层”的可移交子工艺合同，后续可由坎尼会战工艺整合会话纳入完整六层流程。

核心结论：图标生产不是“找一张图抠透明”或“让生成模型随便画一个”。合格图标必须由真实参考、单位数据、生成/重绘工具、分割/后处理、同片质量带、浏览器实际引用、人工视觉复核共同约束，最终以动画地图实际尺寸可读为准。

## 目标

- 产出真实、清晰、有材质的作战单位图标，能在动画地图尺寸下被观众快速识别。
- 同一动画内保持单位类型、阵营、尺寸比例、色彩质感一致，避免黑剪影、灰贴片、照片卡、几何示意和简笔占位。
- 把一次成功修图沉淀为可复跑工具链、质量带、证据和门禁，而不是靠单次手工经验。
- 让每个运行图标都有来源、候选、加工步骤、运行路径、版本号、指标、contact sheet 和浏览器关键帧证据。

## 输入合同

进入图标生产前，必须先明确以下输入。缺少这些输入时，不应直接开生成模型或改运行资产。

- 战役与时代：古代、近代、二战、冷战、现代等，决定服饰、装备、材质、武器和音画语义。
- 阵营与单位清单：每个 `unitSet` 对应一个明确资产，不能依赖组件默认 fallback。
- 角色与地图尺度：主战单位、辅助单位、指挥单位、侦察单位、空中/地面/海上单位的显示层级不同。
- 相对比例：同片内先定比例关系。例如伦敦空战中 Bf 109 小于 Spitfire/Hurricane，Bf 110 更宽，Do 17/He 111 作为轰炸机最大但不能压住航迹。
- 真实源图与参考资料：源图用于约束真实外形、配色和局部细节；数据用于补足视角、比例、部件和阵营标识。
- 目标视角：侧视、俯视、近俯视、三分之二视角必须服从地图可读性。伦敦空战侧视飞机太薄，最终改为俯视/近俯视。
- 目标风格：动画内一致、游戏单位质感、材质可读、阵营可辨，不追求照片原样贴上地图。
- 运行约束：图标实际渲染宽高、LOD、镜像/朝向规则、地图背景颜色和镜头距离。

## 工具链

推荐工具链按职责分层，不要把任一工具当成全流程替代品。

- 素材发现：Wikimedia、博物馆/档案馆、图片站、项目/游戏美术参考、用户提供源图、本地素材库。素材质量优先，来源和不确定性记录为发布风险，不应成为保留丑占位的理由。
- 源图筛选：保留候选记录，筛掉角度严重不适合、主体过小、遮挡严重、背景压住轮廓、关键部件缺失且难以补足的图。
- 生成/重绘：ComfyUI/SD、ControlNet、局部重绘、图生图、风格/材质增强。输入应包括源图、单位数据、目标视角、部件补全要求、阵营特征、色彩和质感要求。
- 分割/抠图：BiRefNet、ISNet、rembg 或同类模型。抠图是中间步骤，不是质量终点。
- 后处理：PIL/OpenCV/ImageMagick 等用于裁切、透明边缘、亮度、饱和度、对比、锐化、阴影清理、局部色彩融合、部件补全后的 alpha 约束。
- 审计：`tools/tactical-terrain-studio/unit-asset-package.py` 负责把运行资产、源图、候选、contact sheet 和基础指标登记为 `unitAssetPackage`。
- 运行验证：Playwright 和专项浏览器 probe 检查实际 DOM href、HTTP 缓存、运行尺寸、fallback 数量、地图关键帧截图和像素连通域。

## 标准流程

1. 建立单位资产清单

   从动画数据或 terrain spec 中列出每个阵营、单位类型、运行 `assetId`、期望 marker 尺寸、默认朝向和比例层级。禁止先生成一堆图再回头硬塞。

2. 收集真实源图和单位数据

   每个单位至少要有一张清晰真实参考图和必要数据。飞机需要翼展、机长、发动机数、翼型、尾翼、阵营涂装；车辆需要炮塔、炮管、履带/轮式、车体比例；步骑兵需要头盔/甲胄、武器、盾牌、马体/骑手关系；舰船需要舰体、帆/烟囱/舰岛、主炮或甲板特征。

3. 生成候选，不直接覆盖运行资产

   候选必须先输出到 `artifacts/`，包括源图输入、控制参考、原始输出、透明候选、metrics 和 contact sheet。运行 PNG/WebP 只有在人工筛选和门禁通过后才能 `--apply`。

4. contact sheet 人工筛选

   contact sheet 要同时展示源图、生成 RGB、透明候选和最终候选。人工先判定是否像目标单位、关键部件是否完整、视角是否可读、质感是否统一。不能因为 alpha 透明就宣布完成。

5. 工具重绘、补全和立体化

   对源图不足的部分，用生成模型补足飞行态、尾翼、机翼、武器、炮管、马腿、舰桥、桅杆等关键识别件。提示词要明确“按单位数据补全”，不能让模型被低质量源图边界限制死。对伦敦空战这类地图小图标，要强调游戏单位质感、金属/蒙皮纹理、较深但不发黑的色彩、俯视/近俯视轮廓。

6. 透明化与裁切

   分割 alpha 应与单位包络相交或局部修补，不能把 photo mask 和分割结果做宽泛并集。伦敦的失败说明：边角透明但主体内部仍是矩形照片背景，根因是背景差异被重新并进 alpha。

7. 同片质量带校准

   选一个已经通过人工视觉复核的代表资产做同片质量基准。伦敦以 He 111 作为基准，把亮度、亮度标准差、饱和度、上下翼平衡、尾翼连接和尾翼-机身色彩连续性转成门禁区间。其他同类资产不必数值完全相同，但必须落入可接受区间并在视觉上同片统一。

8. 应用运行资产与版本号

   覆盖运行资产时必须同步更新版本参数或 hash 路径，并确认本地预览服务对单位图标不使用 immutable 长缓存。用户截图显示旧图时，先查 DOM href、HTTP cache header、发布目录指纹和浏览器请求，而不是先改阈值。

9. 浏览器关键帧证据

   在真实动画页面采样开场、中段、高潮、结尾等关键帧，保存截图和 metrics 到 `artifacts/`。按用户约束，截图和 contact sheet 默认不嵌入会话。

10. 文档与记忆沉淀

    将源图、工具命令、输出目录、版本号、质量带、失败根因、人工复核结论和未自动化规则写回 `docs/sources/<animation>.md`、`docs/sources/unit-icons.md`、更新日志和 mempalace。

## ComfyUI 使用规则

ComfyUI 是第 4 层资产生产工具，不是动画工作流总控，也不是自动素材搜索器。它的价值在于把真实源图和单位数据加工成动画可用图标，包括视角重构、材质增强、部件补全、局部重绘和背景移除。

提示词和工作流必须包含：

- 单位准确名称、时代、阵营、用途。
- 目标视角和地图用途，例如 top-down tactical game unit icon、near-orthographic dorsal view、side-view underway ship marker。
- 关键部件清单，例如飞机机翼、尾翼、座舱、发动机、螺旋桨；车辆炮塔、炮管、履带；步兵头盔、身体、武器；骑兵马体、骑手、武器；舰船舰体、甲板、舰岛/桅杆。
- 材质要求，例如 metal/fabric skin、panel lines、canopy highlight、painted camouflage、not flat grey、not black silhouette。
- 色彩要求，例如 darker than source but not black、higher saturation、faction-distinct markings、consistent with accepted reference asset。
- 负面约束，例如 no landing gear, no museum stand, no runway, no rectangular photo background, no missing tail, no broken wing, no warped fuselage, no cartoon, no schematic placeholder。

当源图是地面展示、缺尾翼、起落架明显或角度不理想时，不应把前置抠图做到极致后再让模型被坏轮廓锁死。更合适的做法是把清晰源图、单位数据、控制参考、修复 mask 和强提示一起交给 ComfyUI，让它先做飞行态/作战态/完整体态，再进入分割和后处理。

## 通用质量标准

- 真实参考：源自真实照片、历史绘画、档案、可靠插画、用户认可参考或项目自制高质量资产，不能用几何图形、简笔画或通用占位冒充。
- 外形准确：观众能在地图尺寸下看出“这是什么单位”，且关键部件完整。
- 材质可读：有金属、布面、木质、甲胄、皮革、舰体、履带、翼面等材质层次，不是黑块、灰块或过曝白片。
- 阵营可辨：同类单位如果敌我都有，应通过外形、颜色、徽记、装备或局部标识区分，不只靠路线颜色。
- 比例合理：同一动画内单位大小符合战场语义和真实比例层级，不能所有资产塞进同一个正方形框。
- 透明干净：边缘、四角和主体内部不能残留照片背景条、地面、展架、跑道、海面、阴影板或白底卡。
- 地图可读：最终以动画实际 marker 尺寸和背景色下可读为准，大图看着好不等于地图上合格。
- 运行真实引用：页面实际使用新资产，无 generic fallback，无旧缓存，无发布目录残留。

## 数据化门禁

基础图像指标可进入 `unitAssetPackage` 或专项 Playwright/probe：

- `alphaRatio`：可见 alpha 总量，防止整张图几乎不透明。
- `bboxRatio`：主体外接盒占画布比例，防止照片卡铺满画布。
- `bboxFillRatio`：外接盒内部填充率，防止主体内部仍是矩形背景。
- `cornerAlphaMax`：四角透明度，防止明显背景卡。
- `edgeVisibleRatio`：边缘可见像素占比，防止贴边背景。
- `maxRowCoverage` / `maxColumnCoverage`：防止长条照片或整行整列背景。
- `luminanceMean` / `luminanceStdDev`：防止黑剪影、洗白和平灰。
- `saturationMean`：控制同片色彩饱和度和阵营可读性。
- `darkVisibleRatio` / `lightVisibleRatio`：防止大面积过黑或过曝。

部件完整性指标按单位类型扩展：

- 飞机：`topBottomBalanceRatio`、`tailJoinRatio`、`tailRootRearFuselageRgbDistance`、左右翼面积差、发动机/座舱可见性。
- 车辆/坦克：炮塔-车体连接、炮管长度与方向、履带/轮廓可见比例、车体左右平衡。
- 步兵：头盔/头部、躯干、武器可见性，武器与身体连接，阵营色块占比。
- 骑兵：马体、骑手、马腿/尾、武器可见性，骑手与马体连接。
- 炮兵：炮管、炮架、轮子/底座可见性，炮管与炮身连接。
- 舰船：舰体长度、甲板/舰岛/桅杆/烟囱可见性，舰体水平度，水线或背景残留。

门禁必须有区间，不应追求所有资产数值一样。伦敦 He 111 标准带示例：

- `luminanceMean`: `80-150`
- `luminanceStdDev`: `46-88`
- `saturationMean`: `45-95`
- `topBottomBalanceRatio`: `> 0.82`
- `tailJoinRatio`: `0.028-0.1`
- `tailRootRearFuselageRgbDistance`: `< 32`

Bf 109 的问题说明部件连接不能只看几何连接。它原本尾翼几何连上了，但尾翼根部与后机身色彩距离约 `36.1`，视觉上像贴片；修复后降到约 `13.4`，并为 Bf 109 设更严的生成目标 `< 22`。

## 人工视觉复核

自动门禁只负责拦截高风险回归，不能替代人工视觉判断。必须人工复核：

- 源图是否真实、清楚、方向合适。
- 生成结果是否像目标单位，而不是像另一个型号或通用幻想资产。
- 部件是否缺失、歪斜、断裂或被源图坏边界限制。
- 色彩和质感是否达到同片基准。
- 地图实际尺寸下是否清楚，不是只在大图 preview 中好看。
- 镜头关键帧里是否被背景、路线、字幕、阴影、烟雾或其他单位遮住。
- 用户截图一律视为最高优先级事实；截图暴露的问题要回到运行页面和证据链排查。

视觉证据保存规则：

- contact sheet 保存到 `artifacts/<asset-run>/contact-sheet.png`。
- 浏览器关键帧保存到 `artifacts/<visual-run>/`。
- metrics 保存为 JSON，包含运行 href、HTTP cache、fallback 数量、console/page errors、图像质量指标和关键帧风险。
- 会话中默认不展示图片，除非用户明确要求。

## 反模式

- 直接把整张照片贴上地图。
- 用几何示意、简笔画、通用 silhouette 冒充生产图标。
- 只看边角透明就宣布抠图完成。
- 前置抠图过度追求干净，反而把生成模型锁死在残缺轮廓里。
- 让 ComfyUI 只围着坏源图边界打转，不给单位数据和部件补全要求。
- 所有单位强塞同一正方形 marker，破坏比例和识别度。
- 大图看着漂亮，但地图实际尺寸下一团糊、太薄或太暗。
- 运行资产已覆盖但 DOM href 没变，浏览器继续读旧缓存。
- 只写测试，不做浏览器截图和人工视觉复核。
- 单次手工修图成功后，不把质量带、脚本和失败根因沉淀回工具链。

## 交给六层工艺整合会话的建议

本文件建议作为第 4 层“作战单位资产、尺度与贴地层”的子工艺引用，而不是并入 AGENTS.md 的仓库级规则。

建议整合点：

- 在第 4 层入口条件中加入“单位资产清单、真实参考、相对比例、目标视角、目标风格”五项输入。
- 在第 4 层输出中加入 `unitAssetPackage`、运行资产路径、版本号、marker 尺寸、默认朝向、LOD 策略、contact sheet、质量 metrics 和浏览器证据路径。
- 把 ComfyUI/SD、分割模型、PIL/OpenCV 后处理写成第 4 层可选工具链，不要把它们提升为全局动画流程。
- 把 `unit-asset-package.py` 作为通用登记和基础审计工具；战役专用生成脚本负责生成、修复和 `--apply`，但必须回填 package。
- 把“先候选、后 contact sheet、再 apply”的流程写成硬规则，防止候选直接覆盖运行资产。
- 把“同片质量带”纳入验收方式：每个动画选一个通过人工视觉复核的基准资产，再把亮度、纹理、饱和度、部件连续性和比例层级转成区间门禁。
- 在第 6 层视觉证据中要求检查运行 href、缓存头、fallback 数量和浏览器关键帧，不只检查文件存在。
- 对坎尼会战等阵法战，优先补充步兵、骑兵、指挥单位的头盔/甲胄/武器/马体/旗帜/阵营色质量带，而不是照搬飞机的尾翼指标。
- 对后续海战、装甲战、航空战，分别建立舰体、炮塔/炮管/履带、机翼/尾翼/发动机等单位类型指标。

伦敦经验可以直接作为整合案例：

- 失败一：照片卡通过了简单透明门禁。修正为分割 alpha 与单位包络相交，并增加 bbox/row/column 覆盖指标。
- 失败二：浏览器显示旧图。修正为版本化 href、`Cache-Control: no-cache` 和浏览器请求证据。
- 失败三：侧视飞机太薄。修正为真实源图加单位数据生成俯视/近俯视图标。
- 失败四：尾翼几何连接但颜色像贴片。修正为部件色彩连续性指标。
- 成功点：以 He 111 成品建立同片质量带，再推动其他机型向同一质感和色彩标准收敛。
