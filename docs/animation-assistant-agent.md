# 动画助手智能体设计

## 定位

动画助手负责把一个主题转成“可播放、可暂停、可回放、可拖拽时间轴、可验证、可常驻运行”的网页动画作品。它不是单纯写页面，而是完成从资料、数据模型、视觉叙事、交互控制、自动化验收到长期复用记忆的闭环。

已沉淀为 Codex Skill：

- `agents/skills/animation-assistant/SKILL.md`
- `agents/skills/animation-assistant/references/prompt-patterns.md`
- `agents/skills/animation-assistant/references/battle-france-retrospective.md`
- `agents/skills/animation-assistant/scripts/check-animation-project.mjs`

## 本次开发复盘

### 阶段 1：从试验项目到可运行页面

- 创建桌面项目 `战争动画藏书馆`。
- 采用 Vite + React + TypeScript，保持轻量。
- 建立 `src/data`、`src/lib`、`docs/sources`、`tests`。
- 用结构化数据驱动二战德法战役时间线。
- 实现播放、暂停、回放、时间轴拖拽和事件跳转。

### 阶段 2：从手绘地图到真实地图

- 初版手绘 SVG 地图粗糙，用户反馈有效。
- 引入 `d3-geo`、`topojson-client`、`world-atlas`。
- 把城市和事件点从像素坐标改为真实经纬度。
- 发现 `fitExtent` 使用 Polygon 可能被球面方向解释错，导致地图缩成一团。
- 修复为 `MultiPoint` bounds。

### 阶段 3：从粗箭头到军事态势表达

- 用户反馈态势线过粗、遮挡地图。
- 改为细线、弱光晕、方向虚点。
- 德军推进线加入坦克引导符号。
- 当前战役点加入爆炸冲击波，过后保留静态战斗星标。

### 阶段 4：从固定视角到阶段镜头

- 后期战役向法国南部和巴黎/贡比涅发展，固定北法视窗看不到后续。
- 先尝试 SVG transform/camera follow，和 `preserveAspectRatio=slice` 组合不稳定。
- 最终改成阶段化投影视窗：北法/低地国家、法国本土、巴黎-贡比涅。

### 阶段 5：从一次性演示到常驻产品

- 原私有工作区曾用 macOS LaunchAgent 常驻运行生产预览。
- 开源仓库默认不附带本机服务文件；如需常驻运行，可按 `animation-assistant` skill 的通用运行章节自行创建。
- 推荐使用 `npm run preview` 服务生产构建产物，并用 `lsof`、`curl -I` 或浏览器 smoke 验证。

## 稳定工作法

1. 先读项目，不凭空改。
2. 先建数据模型，再写动画。
3. 事实内容必须有来源文档。
4. 视觉问题以用户截图为准。
5. 每次修复都沉淀一个可测试的回归点。
6. 本地长期作品必须常驻运行。
7. 成功经验写入 skill 和 mempalace。

## 战争系列规则

- 默认入口应是战争系列主页，而不是某一部动画。
- 主页按“古代战争 / 现代战争”分架：拿破仑时代及其后的战争归入现代战争，更早战争归入古代战争。
- 后续战争动画标准片长为 5 分钟；根据战争节奏选择 `playbackDurationSeconds`，播放速度就是 `1 / playbackDurationSeconds`。
- 长时段战争必须浓缩为关键节点，不按日完整播放。
- 战区反复拉锯时，不重复堆叠同一路线；用“区域/战区 + 第N次作战”或“第N阶段”标注。
- 公元前战争使用 `BCE-YYYY-MM-DD` 内部日期格式，并由时间轴工具格式化显示，避免浏览器负年份兼容问题。
- 新动画优先复用 `CampaignMapAnimation`：数据在 `src/data`，镜头在 wrapper 组件，来源在 `docs/sources`。
- 地图上的标题/副标题只能做小型角落情报牌，不得大面积遮挡地图；长标题截断，详细叙事放右侧故事栏。
- 敌我双方态势线必须同时具备颜色和线型差异，并通过图例说明攻势、反攻、撤离或特殊行动。
- 系列中每部战争动画优先使用不同的高质量成品配乐；不可所有动画重复同一首进行曲。
- 配乐唯一性必须进入回归测试：每部动画的 `score-toggle` 或同等控件暴露 `data-music-source`，smoke 遍历所有已注册战争动画并断言背景配乐路径不重复，除非用户明确要求复用。
- 配乐质量也是验收项：不要用低码率、单声道、听感像档案留声机的军乐来交付电影化战争动画；除非用户明确要档案感，否则优先选择完整、立体声、听感适配战役气质的成品配乐。临时低质配乐必须标记为占位并在交付前替换。
- 战争动画的单位图标和音效必须按时代匹配：古代陆战用骑兵/战车图标和刀剑/冷兵器撞击声，古代海战用战船图标和海上航线；拿破仑时代用火炮图标和炮声；二战装甲战用坦克图标；二战航母战/海空战用航空母舰图标，不要混用普通战船；只有现代火力战才使用爆炸、飞机、扫射等音效。
- 空袭/航空作战路线必须使用写实飞机图标和 `routeKind="air"`，不能让空袭线显示坦克、战马或其他地面单位。海湾战争这类现代空地战要区分空袭线和地面装甲线。
- 战役音效不能只绑定播放循环。事件列表/事件轨点击也必须在用户手势内触发对应时代 SFX；古代战役点击应播放 `swords-clashing`，拿破仑战役点击应播放炮声，现代战役点击按配置播放俯冲/炮爆/扫射。Playwright 应 mock `Audio` 并断言点击关键事件时请求了正确 SFX 路径。
- `cueEvents` 不能只列高潮战役。每个战斗、围城、突袭、渡河/登陆、强攻事件都应有时代匹配音效；继位、死亡、条约、纯政治节点可保持静音。测试要批量点击代表性战斗事件，不能只测一个名战役。
- 海战路线必须走海面，必要时增加港口点和 `waypoints`，不能为了连接两个历史地点而把海路画在陆地上。
- 长跨度、节点稀疏的战争可使用压缩时间轴，把大段无事件间歇缩短以提升节奏；但苏德战争这类多线并进的战争应保留统一日历轴，让没有进展的线自然停顿，避免因各线独立压缩造成战场轴线混乱。
- 多场战争合并叙述时，要显式识别和约束两场战争之间的休战/和平空白，必要时把它们压成固定短过场；只做比例压缩仍可能留下明显“死时间”。
- 对布匿战争、拿破仑战争这类长跨度但作战节点离散的动画，时间轴应按“有效作战段”计算：用路线/战役线的 `start/end` 生成 active spans，非作战间歇不计入播放轴，而不是把整段历史日历混在一起压缩。
- 战争动画默认按周显示和推进感知，避免按日显示导致观众觉得推进太慢；具体事件仍可保留准确日期作为资料字段。
- 短战争或短会战不能硬套周粒度。若战斗集中在数小时到数日内，数据日期可使用 `YYYY-MM-DDTHH:mm`，`timeStepDays={1 / 24}` 并把 `timeCounterLabel` 设为“小时”；地图视窗应收紧到战场本身，让战术走位清楚可见。
- 启用压缩时间轴时，镜头切换、事件跳转、路线推进和事件轨道必须使用同一套压缩映射；不能只压缩播放进度却让镜头锚点仍按未压缩日历计算。
- 压缩时间轴里如果有临时战区外跳，例如凯撒战争从高卢短暂切到不列颠，必须在下一段作战开始时显式切回原战区；不能假设前一个大章节镜头自然恢复。回归断言应检查事件标签组整体落在地图核心区，而不只是经纬度点本身。
- Playwright 如果跑的是 `vite preview` 产物，源码改完必须先 `npm run build` 再跑浏览器 smoke；否则测试可能仍在旧 `dist` 上失败或误过。
- 战车、战马、大炮、战船、航空母舰、坦克等单位图标不能停留在抽象简笔符号水平，应使用有层次的写实 mini-illustration：战车要能看出车厢/车轮/驭手，战马要能看出马体/骑手/武器，战船要能看出帆/桨/船体，航空母舰要能看出飞行甲板/舰岛，大炮要能看出炮管/炮架/轮子，坦克要能看出履带/炮塔/负重轮。
- 如果使用成品位图图标，不要把宽主体压进正方形 marker：骑兵、战车、战船要按实际轮廓设置 `UnitIcon` 的 width/height，并用 Playwright 检查 `.unit-icon-image` 的资产路径和 content-length，避免退回占位图。
- 单位图标必须保持水平可读，不跟随态势线坡度旋转。态势线和箭头负责表达角度；坦克、战马、战船、航空母舰、大炮、战车只根据当前路线段的左右方向镜像，且要考虑素材默认朝向。路线刚开始、当前位置和起点重合时，用下一段非零路线作为朝向 fallback。
- 旁白字幕必须是地图内低高度、半透明、横向滚动 ticker，`pointer-events: none`。字幕不能与底部控制台重叠；底部控制台不得 sticky 覆盖地图，否则会造成“字幕不挡但控制台挡”的假象，也会让滚轮/拖拽误判。
- 地图交互必须纳入通用组件而不是单部动画临时实现：地图 SVG/舞台支持普通滚轮纵向平移、Shift/横向滚轮横向平移、显式放大/缩小/复位按钮、拖拽平移、双击复位；wheel 监听使用非 passive 原生 listener，避免 `preventDefault` 控制台错误。
- 古代中国战史不能用重复纹样或装饰墙纸。若处在统一战争动画库中，优先保留系列通用底图和投影，把古代国界/势力范围画成同一投影下的半透明历史区域叠层；七国边界这类历史信息要补在数据层，不要另起一套特殊底图风格。若是独立古中国地图，可采用完整纸本舆图风格，但边界、河道、路线、事件点仍必须同属 `camera-layer`。
- 缩放不要只依赖 Ctrl/⌘+滚轮，这个手势发现性差、体验不稳定。地图必须提供可见的 `+`、`-`、复位按钮；Ctrl/⌘+滚轮最多作为可选快捷方式。
- 横向移动不能依赖缩放后溢出：默认缩放下也必须给 `x` 方向基础平移余量，否则所有地图都会表现为只能上下移动。wheel 模式必须互斥：普通滚轮只改 `y`，Shift/横向滚轮只改 `x`，缩放按钮只改 scale。
- 修镜头跟随问题时先区分“自动镜头没有跟上”和“用户交互不能移动地图”。苏德战争南线问题属于地图交互缺失，修复后要同时测南线/斯大林格勒事件点在核心区，以及手动滚轮/拖拽可改变 `camera-layer` transform。
- 手动地图位移不能污染后续自动镜头：用户滚轮/拖拽只在当前战区内生效；当 `mapFocus`/视窗阶段变化时必须复位 `camera-layer` 的平移缩放，否则后续事件跳转会带着旧偏移，看起来像镜头没有跟上。
- 跨日期线战区必须有专用投影策略。太平洋战争这类使用 `0-360` 经度的动画应旋转投影到太平洋中心，并按珍珠港、中太平洋、南太平洋、马里亚纳、菲律宾、日本外围拆分视窗；用 Playwright 断言关键事件点在地图核心区。
- 长跨度岛链/海战动画不能保留完整日历空档。太平洋战争这类瓜岛后进入阶段性岛链推进的动画，应从路线 `start/end` 生成 `activeSpans`，启用 `timingMode="compressed"`，给非作战空档短固定显示时长，并用事件轨道间距测试防止瓜岛之后再次空转。
- 新增现代战争动画时，先检查现有 `musicSource` 列表，再下载/记录一首新的高质量成品配乐。不要为了赶进度复用旧动画配乐；配乐唯一性测试必须覆盖新入口。
- 对马海战这类战术走位复杂的短海战，地图不要扩到整个东北亚。优先使用近景海峡/海湾视窗，显示双方航向、横切、主战区、夜战追击和失败单位退场。不要把此类海战画成尾随追击；应先查资料拆成侦察接触、转向、第一次横切、旗舰/前导崩溃、第二次横切、夜战和投降等战术段，再画路线。清晨侦察可作为旁白/事件背景，但播放开场必须立即出现舰队和行动路线，不能让用户看半天空海图；东乡转向和抢 T 字横头时，俄舰队必须仍在日舰侧前方/南西侧，不得画成俄军已经越过日舰航线。
- 近代海战 `warship` 图标要优先使用航行态侧视舰船照片/绘图，避免设计图、俯视图、三视图或纸面蓝图感太重的素材。素材默认朝向要写入 `UnitIcon` 宽高和 `defaultFacingX`，并测试图标水平、只按左右方向镜像。
- 动画库战争越来越多时，不要继续在页面全局顶/底部堆所有战争入口；保留首页卡片入口，把全局区域改成固定身份/题铭/说明。卡片打开动画时必须重置滚动到顶部，避免地图加载到视口外导致滚轮/拖拽命中失败。
- 装饰性 SVG 图层必须有明确 scoped 样式。新增 `terrainZones`、椭圆、纹理等元素时要显式设置 `fill/stroke/opacity`；缺样式会按 SVG 默认黑色填充，形成遮挡地图的大黑块。

## 标准提示词

```text
使用 animation-assistant，把 <主题> 做成一个数据驱动的交互式网页动画。

要求：
- 收集并记录资料来源。
- 用结构化数据表达事件、路径、时间轴和镜头阶段。
- 实现播放、暂停、回放、时间轴拖拽、事件跳转。
- 全片控制在5分钟，并说明 `playbackDurationSeconds` 如何设置。
- 如出现拉锯战或重复路线，用“区域/战区 + 第N次作战”分层，不要反复画粗线。
- 地图顶层标签要小，不遮挡关键地理和态势线。
- 古代中国战史优先保持系列通用地图风格，把七国/势力边界补成同投影数据叠层；不要用重复山纹、经纬网或纯装饰纹样来替代真实边界。
- 区分敌我双方态势线：颜色、虚实、图例都要不同。
- 背景配乐要按动画分别选择，记录许可、署名、码率和时长。
- 按时代选择图标和音效：古代陆战骑兵+刀剑声，古代海战战船+海路，拿破仑时代大炮+炮声，二战坦克+现代火力声。
- 战车、战马、大炮、战船、坦克必须采用写实、有细节层次的图标，不能用抽象简笔画。
- 单位图标保持水平，只按路线当前左右方向镜像，不能随路线角度侧立或倒立。
- 地图必须保留滚轮平移、显式缩放按钮、拖拽平移、双击复位，字幕和遮罩层不得拦截地图交互。
- 自动镜头切换时复位旧的手动平移/缩放；跨日期线地图必须旋转投影并分战区验证关键事件可见。
- 默认缩放下也要支持左右拖拽/横向滚轮；长跨度稀疏战役要压缩非作战空档，并测试后半段事件轨道间距。
- 长跨度战争要按有效作战段计算时间轴，剔除战役间歇；多线并进战争保留统一时间轴，让无进展路线停顿，不能压乱整体战场时序。
- 默认按周显示当前进度，避免按日推进造成节奏拖沓。
- 短战争例外：按小时/天显示当前进度，不能把一两天战斗显示成“第几周”。
- 动画画面要精美，不要粗糙箭头遮挡内容。
- 用 Playwright 验证首屏、中期、后期状态。
- 生成截图证据。
- 如需长期访问，配置常驻服务。
- 最后把可复用经验沉淀进 skill/mempalace。
```

## 可继续增强

- 增加脚本自动生成 Vite 动画项目模板。
- 增加 GeoJSON/TopoJSON 自动视窗计算脚本。
- 增加视觉评分清单：地图占比、标签重叠、线宽、动态效果节制。
- 增加“旁白字幕轨”和“导出视频/GIF”能力。
